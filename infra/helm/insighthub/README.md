# InsightHub Helm chart

This chart deploys the InsightHub web, API, and ingestion worker into the
Terraform-managed `insighthub-production` namespace. It also runs an idempotent
PostgreSQL migration Job, exposes the web/API through an HTTPS ALB, and mounts
the RDS and Redis connection data directly from AWS Secrets Manager.

## Prerequisites

- The Terraform stack in `infra/` has been applied successfully.
- The `insighthub` IRSA ServiceAccount exists in `insighthub-production`.
- Secrets Store CSI Driver and AWS provider are installed as cluster add-ons.
- AWS Load Balancer Controller is installed with its own least-privilege IRSA.
- Metrics Server is installed when API autoscaling is enabled.
- A Kubernetes NetworkPolicy-capable CNI is enabled. For the AWS VPC CNI,
  enable its network-policy feature before relying on these ingress policies.
- The ACM certificate is issued in the cluster region and covers the selected
  DNS hostname.
- The web, API, and worker images have been pushed to ECR and referenced by
  immutable `sha256` digest.

The chart deliberately does not install cluster-wide controllers. Their IAM
roles and lifecycle are independent from this namespace-scoped release.

## Configure

Copy `values-production.example.yaml` to a private deployment values file and
replace every placeholder. Obtain the secret ARNs from Terraform:

```powershell
terraform -chdir=infra output -raw rds_master_secret_arn
terraform -chdir=infra output -raw redis_secret_arn
```

Do not put plaintext passwords or tokens in Helm values. The chart creates no
Kubernetes Secret: CSI mounts both Secrets Manager JSON documents read-only,
and an init container writes connection environment exports into a memory-only
`emptyDir` shared by the application container.

Set `networkPolicy.vpcCidr` to the same CIDR passed to Terraform as `vpc_cidr`.
The web and API accept ingress only from that VPC CIDR; the worker accepts no
inbound connections. Egress remains controlled by the AWS security groups and
the private-subnet route design.

Replace the documentation-only `ingress.inboundCidrs` entry with approved
operator/client CIDRs. The ALB listens on HTTP only to redirect those clients
to HTTPS; its security group is never generated with `0.0.0.0/0` by this chart.

## Validate

```powershell
helm lint infra/helm/insighthub -f infra/helm/insighthub/values-production.example.yaml
helm template insighthub infra/helm/insighthub `
  --namespace insighthub-production `
  -f infra/helm/insighthub/values-production.example.yaml
```

## Deploy

```powershell
helm upgrade --install insighthub infra/helm/insighthub `
  --namespace insighthub-production `
  --create-namespace=false `
  -f path/to/private-production-values.yaml `
  --atomic --wait --wait-for-jobs --timeout 20m
```

The migration Job runs `CREATE EXTENSION IF NOT EXISTS vector` and the schema
from `files/init.sql`. API and worker pods independently wait for the
`documents` table, so they cannot become active against an unmigrated database.

## Verify

```powershell
kubectl get deploy,svc,hpa,job,ingress,pods -n insighthub-production
kubectl logs -n insighthub-production job/insighthub-insighthub-migration-<hash> -c migrate
kubectl describe ingress insighthub-insighthub -n insighthub-production
curl.exe --fail https://insighthub.example.com/healthz
```

The RDS-managed secret must contain `username`, `password`, `host`, and `port`.
The Redis secret generated by Terraform must contain `password`, `host`, and
`port`. Workload IAM is limited to those two secret ARNs and their KMS key.
